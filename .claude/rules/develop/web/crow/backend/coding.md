# ⚙️ crow / backend — コーディング規約（サーバ側の上乗せ）

> **共通スタイルは [common/coding.md](../common/coding.md)**（インデント表・Allman・snake_case・
> `i_` プレフィックス・`===`／`!` 禁止・コメント `//<TAB>`・80 桁・PHP 閉じタグ・ファイル終端改行）。
> 本書は**それに従ったうえで**、サーバ側（action / model / crow API を叩く PHP）にだけ効く差分を定める。
> 共通側の再掲はしない。

## 現状：backend 固有の上乗せは無い

crow の既存コーディング規約を frontend / backend に仕分けた結果、
**サーバ側にだけ効く記述ルールは現時点で存在しない**（PHP 閉じタグ・`i_` プレフィックスなど
「PHP だから」に見えるものも、crow の view が PHP ファイルである以上 frontend 側も従うため共通に置いた）。

したがって **backend のコードは common/coding.md にそのまま従う**。
無いルールを埋めるために共通側から写してこないこと（二重化は drift の温床）。

## ここに書くもの（育て方）

サーバ側にだけ効く規約が出てきたら、この葉に追記する。想定される関心事：

- `action_*` の置き場・命名・リクエスト受けの作法（`crow_request` 経由の入力の扱い）
- `model_*` と SQL ビルダのチェーン記法・トランザクション境界
- `crow::get_hdb()` などフレームワーク API を呼ぶ際の約束
- エラー・例外の返し方、ログの出し方

> 1 葉が肥大したら関心事ごとに分割する（`backend/model.md` 等）。
> **frontend にも効く話になった時点で、この葉ではなく common/coding.md へ上げる。**
