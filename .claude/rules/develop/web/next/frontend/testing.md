# 🧪 Next.js / frontend — テスト設計

> **適用範囲: Next.js（App Router）の UI 面。** Next.js でなければ本書は適用外として読み捨てること。
>
> **共通則は [common/testing.md](../common/testing.md)**（ランナーはプロジェクト宣言・コマンド一発・
> 決定性・スイート分離・`F-xxx`）。本書は**それに従ったうえで**、
> frontend で「何を・どう」テストするかだけを扱う。共通側の再掲はしない。

---

## 1. 何をテストし、何をテストしないか

| 対象 | 扱い |
| --- | --- |
| **props を与えたときの UI 状態の出し分け**（loading / empty / error / 権限 / 境界） | **テストする。** presentational は props だけで表示が決まる前提。表示の有無・文言・状態を明示アサーションで |
| **読み取り配線の薄い試験**（ユースケースをモックし、不正 params → `notFound`、成功時の props 写像） | **テストする**（§3）。RSC ランタイム全体の起動は必須にしない |
| クライアントだけで完結する UI 状態遷移（意味のある振る舞い） | **テストする**（過剰に細かくしない） |
| **契約の縁（FE 側）** | **必須（既定スイート）。** スライスに更新があるかで対象を分ける（下表）。サーバ本体はモックしてよい |
| ピクセル配置・色・余白 | テストしない。人間の一瞥（develop の 🙋 ゲート） |
| **スナップショットテスト** | **書かない** |
| `page.tsx` の RSC ランタイム全体を立ち上げる重い試験 | **既定スイートでは求めない** |
| Server Actions / Route Handlers の本体（zod・ユースケース・`revalidatePath`・HTTP 縁） | **backend の試験**。ユースケースは**シナリオ結果**、呼び手向け Result／status は BE。混同しない |

契約の縁の対象（どちらか一方で「FE 側の契約適合」を満たす。無い更新口を捏造しない）:

| スライス | FE が既定スイートで必ず見る縁 |
| --- | --- |
| **ミューテーションあり** | 契約された更新口（Server Actions 等）を正しい引数で呼ぶ／戻りを UI props や表示へ写像する |
| **読み取りのみ** | 契約された response 形（またはユースケースの成功データ形）→ ビュー props への写像。§3 の読み取り配線試験で兼ねてよい |

## 2. 要素の引き方

特定ライブラリの API 名は固定しない。ただし次を守る。

1. **可能な限り、ロール・ラベル・名前などアクセシブルな手がかりから要素を引く**
2. 表示テキストは、安定して振る舞いを表すときに使う
3. **テスト専用 ID は、アクセシブルな名前を付けようがない要素への最後の手段**とする

引けないことが実装の a11y 欠落を示しているなら、テスト側で ID を足して回避せず、
**実装側の欠陥として報告する。**

---

## 3. presentational と読み取り配線

### presentational（UI トラックの主戦場）

props を変えて loading / empty / error / 権限 / 境界を切り替える。
通信やユースケースを UI コンポーネント内で起動しない前提で書く。

### 読み取り配線（FE ロジック側の薄い試験）

`page` / `layout` 相当を、**可能な範囲で関数として import**し、次をモックして検証する。

- ユースケース → 固定のシナリオ結果を返す
- `notFound`（および必要なら `redirect`）→ 呼び出し有無を検証できるよう差し替え

見るもの:

- 不正な `params` / `searchParams` のとき `notFound` 等が呼ばれる
- 成功時、ビューへ渡す props がシナリオ結果から正しく写像される

**RSC ランタイムをフル起動する試験は既定スイートの必須にしない。**
ランナー固有のセットアップ手順はプロジェクトの `CLAUDE.md` に書く。外部環境は起動しない（[common/testing.md](../common/testing.md) §4）。

---

## 4. Client と Server Actions

- Client 末端は、**親から渡したコールバックまたは Server Actions** を呼ぶことまでを検証してよい
- Action の中身は backend 試験に寄せる
- UI 試験で Action をモックする場合は、**境界として**差し替える
