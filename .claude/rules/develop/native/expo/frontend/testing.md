# 🧪 Expo / frontend — テスト設計

> **適用範囲: Expo (expo-router) の React Native アプリ。** Expo でなければ本書は適用外として読み捨てること。
>
> **共通則は [common/testing.md](../common/testing.md)**（`jest-expo` preset・コマンド一発・
> RN での決定性・スイートは実行要求で分ける）。本書は**それに従ったうえで**、
> frontend で「何を・どう」テストするかだけを扱う。共通側の再掲はしない。
>
> テストも [common/coding.md](../common/coding.md) と [coding.md](./coding.md) の記法規約に従って書く。

---

## 1. 何をテストし、何をテストしないか

| 対象 | 扱い |
| --- | --- |
| 純粋関数（整形・判定・変換・バリデーション） | **テストする。** ここが最も反証力が高い |
| API クライアント（契約に沿った request / response の組み立て） | **テストする。** バックエンドは契約どおりにモックする（**既定スイート**に置く。[common/testing.md](../common/testing.md) §4） |
| **props を与えたときの UI 状態の出し分け**（loading / empty / error / 権限 / 境界） | **テストする。** 表示の有無・文言・状態を明示アサーションで |
| クエリ層の変換（`select` 等） | **テストする** |
| ピクセル配置・色・余白 | テストしない。人間の一瞥（develop の 🙋 ゲート）で確認する |
| アニメーション・遷移の演出 | テストしない |
| ネイティブモジュールの中身 | テストしない。framework とライブラリの責務 |

---

## 2. クエリはアクセシビリティから引く

**優先順位を守る。**

1. `getByRole`（`{ name }` を併用して同定する）
2. `getByLabelText`
3. `getByText`
4. **`getByTestId` — アクセシブルな名前を持ちようがない要素に対する最後の手段**

この順序が成立するのは、実装体が [coding.md](./coding.md) §5 に従って
`accessibilityRole` / `accessibilityLabel` / `accessibilityState` を**発行している**からである。

**引けない要素があったら、それはアクセシビリティ属性の欠落という実装側の欠陥である。**
`testID` を足して回避しない。**欠陥として報告する。**

---

## 3. スナップショットテストを書かない

RN のツリーはシリアライズすると巨大で、差分は誰もレビューせず、赤くなれば `-u` で緑になる。

**意図を符号化しておらず、反証力がほぼゼロである。** これは「壊れていることを摘発する」という
テストの任務と正面から矛盾するので、書かない。

代わりに、**「この props ならこの表示になる」**を明示的にアサートする。

```tsx
//  NG
expect(render(<UserCard user={user} />)).toMatchSnapshot();

//  OK
render(<UserCard user={user} />);
expect(screen.getByRole('button', { name: '編集' })).toBeDisabled();
expect(screen.queryByText('削除済み')).toBeNull();
```

---

## 4. モックするのは境界＝ネイティブ側と通信だけ

`jest-expo` が面倒を見ない範囲は**明示的にモックする。** ここを外すと
**「import した瞬間に落ちる」**タイプの失敗になり、テスト対象と無関係な場所で時間を溶かす。

代表的な要モック対象: `expo-router`、`expo-secure-store`、`react-native-reanimated`、
safe area のインセット、通知・カメラ・位置情報などのネイティブモジュール、通信。

**内部ロジック・自作フックはモックしない。** モックだらけのテストは実装の写経になり、反証力を失う。

---

## 5. 非同期とタイマー

- 押下・入力は `userEvent` を優先する（`fireEvent` は実機の挙動から離れる）
- 非同期の出現待ちは **`findBy*` / `waitFor`** で書く。**実時間の `sleep` を書かない**
- タイマー・デバウンス依存はフェイクタイマーで進める。実時間を待たない

---

## 6. リストとルーティングの落とし穴

- **`FlatList` は可視範囲しか描画しない。** 画面外の行に対するアサーションは落ちる。
  先頭ページに含まれる行で検証するか、テスト用に件数を絞る
- **ルーティングを含む検証は expo-router のテストユーティリティを使う**（ナビゲータを自前で組み立てない）。
  自前で組むと本番の解決経路と別物になり、緑が何も保証しなくなる

## ✅ テスト着手前チェックリスト

- [ ] 対象の GWT 受け入れ条件（orchestrator が渡す）を先に確認したか
- [ ] ランナーが導入済みで、1 コマンドで全件実行できるか（[common/testing.md](../common/testing.md) §2）
- [ ] 書こうとしているテストは外部環境を起動するか（起動するなら既定スイートの外へ。[common/testing.md](../common/testing.md) §4）
- [ ] 検証対象の props 型（＝実装体どうしの契約）が決まっているか
- [ ] 失敗・空・権限・境界のケースを起票したか
- [ ] スナップショットに逃げていないか
- [ ] モックが境界だけに閉じているか
- [ ] **Red を起こせない入力（UI 状態が GWT に列挙されていない／props 契約が未定）に当たったら、
      書かずに止めて報告する**
