# ✍️ writing — 執筆の指揮者（orchestrator）

> 記事・ブログ・技術解説を書く／直すときの入口。型の SSOT は rules の [blog.md](../../rules/routines/writings/blog.md)（非常駐・この skill が明示 Read する）。本 skill は **どう回すか** を担い、型の中身は複製しない。

## 0. まず型を読む（必須）

[blog.md](../../rules/routines/writings/blog.md) を Read し、**構成の型・文体/トーン・推敲チェック**を頭に入れる。

## 1. 不変則（作る主体 ≠ 推敲する主体）

- rules コア原則「**成果物を作った主体と、判定する主体は別コンテキストにする**」に従う。書いた本人が推敲すると同じ思い込みを見逃し、批判が甘くなる。
- この skill を起動したエージェントは **orchestrator** に徹する。人間と話して要件（読者・核メッセージ・媒体）を固め、**下書き**と**推敲**をそれぞれ別サブエージェント（Agent ツール）に委ねる。**自分では書かない・推敲しない**（兼ねると中立を失う）。
- 規模で調整: 短文（数段落）は 1 パス可。**記事規模は必ず writer → reviewer を分ける。**

## 2. 起動シーケンス

| 局面 | 主体 | 人間ゲート |
|---|---|---|
| 要件固め | orchestrator（インライン）: 読者・**1記事1メッセージの核**・媒体・長さを確定 | 🙋 核メッセージを人間承認 |
| 下書き | `writer` サブエージェント | — |
| 推敲 | `reviewer` サブエージェント（別コンテキスト） | — |
| 引き渡し | orchestrator が統合して提示 | 🙋 最終稿を人間確認 |

- **writer**: blog.md の「構成の型」（フック→結論→本論→まとめ→次の一歩）と「文体・トーン」に沿って本文を書く。読者価値ファースト・結論先出し・一文一義。
- **reviewer**: 下書きを作っていない**別サブエージェント**。入力は下書きと blog.md の推敲チェックだけ（writer の思考過程は渡さない）。仕事は "OK 確認" でなく**反証（粗探し）**——タイトルと結論の不一致・冒頭3行の価値・1メッセージ超過・具体例の欠落・冗長・次の一歩の欠落を突く。

## 3. 完了チェック（blog.md の推敲チェックに委譲）

blog.md の推敲チェックリスト（タイトル=結論／冒頭3行で価値／1記事1メッセージ／具体例で裏付け／次の一歩／削り切り）が **reviewer で埋まった**こと。埋まらなければ writer に差し戻す（自分で直して自分で OK にしない）。

> **原則:** この skill は blog.md の中身をコピペしない。手順の骨格だけを持ち、判断基準は blog.md（＝SSOT）に委譲する。
